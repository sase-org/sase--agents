## What I found

**Your premise is half right, and the half that's wrong is the important half.** There is no per-plugin "dev mode." Per plugin there are exactly two sources: index and git. *Editable* is a property of the whole environment (`sase update --to dev|pypi`), which converts every package at once. So "just use the dev install instead" isn't something you can do for one plugin — that command doesn't exist.

**Why `-g` exists:** the original plan (`plans/202606/sase_update_and_plugin_install.md`) specified index-by-default with a git fallback *"for catalog plugins not published to an index,"* and `-g` merely to force it. The automatic fallback was never implemented. `-g` is the manual workaround for a gap the design meant to close automatically.

**`-g` isn't why `bugyi-chops` is on git.** One publish attempt ever: `v0.3.1`, 2026-07-27, failed in 19s with `invalid-publisher` — a PyPI trusted publisher that was never created. Repo is now at 0.7.0, untagged.

**Two migration traps, both verified empirically:**
- After `--to dev`, `dev_route_from_inventory` routes only `sase`, `sase-github`, `sase-telegram`, `sase-core-rs` — `bugyi-chops` is **silently dropped** and `sase update` would never fetch its checkout again. It has no `sase-*` name, `sase_*` entry point, or `sase_chop_*` script, so it isn't in the version inventory at all.
- `--to pypi` then reconstructs a bare `--with bugyi-chops` → PyPI 404 → and since it's one `uv tool install` for the whole set, **the entire environment's switch fails**.

**Git installs are already second-class**, which is the strongest support for your instinct: `sase-research-artifacts` (also a git install) is misclassified as `wheel`/index while `bugyi-chops` is classified correctly only by accident; git installs get no freshness comparison at all; and SASE's own automated install paths (batch install, the `PluginsRequired` gate) already hardcode `git=False`, so an unpublished plugin can never be auto-installed.

## Recommendation

**Fix the PyPI publisher first.** It dissolves the proximate problem, restores reversibility, and costs almost nothing. Then move both git rows to the index with uninstall+install (install/update alone won't switch source — `with_upgraded` preserves the git row). `sase-research-artifacts` can be done today; it's already on PyPI at exactly the installed version.

Treat `-g` removal as optional and *following* three prerequisites: fix `_source_for_entry`, make receipt-owned packages first-class in the version inventory (the half of `fix_receipt_owned_plugin_detection` scoped out in July), and add a per-plugin `--to dev|pypi` source switch. Only then retire `-g` behind a `sunset` flag. Receipt-level git tolerance stays permanently — SASE doesn't own `uv-receipt.toml`.

Where the two reports disagreed (classification, tolerance duration, which prerequisite blocks, and the shape of the missing command), §9 records each resolution with the evidence.
