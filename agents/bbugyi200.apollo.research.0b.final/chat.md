1. **Agent order.** `audio=true` should start the linker, and the linker should wait for the audio agent before writing the report. Today neither is true: audio doesn't start the linker, and the linker doesn't wait for it. Audio still starts right after the lead, alongside the image agent. On real swarms audio finishes about when the image does, so the wait costs nothing with an infographic and about 10 minutes without one.
2. **Storage.** The audio agent saves the MP3 next to the report as `<name>_narration.mp3`, committed like the infographic. One relative link then works in every checkout, on GitHub, and when the PDF is built.
3. **Markdown.** One fixed line closes the research-query quote at the top: `▶ **Listen:** [4-minute narrated brief](<name>_narration.mp3)`.
4. **`bob highlights create` / `scan`** gain a general "local audio links" feature:
   - `create` copies the MP3 next to the PDF in the queue and rewrites the PDF's link to an `obsidian://` URI. The URI format is a config setting, so you can swap it later without code changes.
   - `scan` moves the MP3 into `lib/` with the PDF.
   - The Obsidian reference note gets a native audio player directly under the "open PDF" task.

- **"Listen first", not "listen while reading".** The brief is a 4-minute summary, not the report read aloud. That's why the link sits at the top and shows the length.

The repo is public, so I made sure no feed tokens, tailnet hostnames or host paths ever go into a report. A brief is about 2.2 MB, roughly 1.7 infographics.
